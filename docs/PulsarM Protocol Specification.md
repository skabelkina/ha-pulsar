# **PulsarM Protocol Specification**

Version: 1.0  
Date: 2019-05-23  
Target Audience: Developers

## **1\. Data Link Layer**

The communication interface operates using octets (bytes) as payload data. The protocol supports half-duplex operation.

### **Timing Characteristics**

* $T\_s$ **(Inter-character delay):** Maximum delay between characters within a single frame. This depends on the specific communication interface. If this time is exceeded, the device considers the frame transmission complete.  
* $T\_e$ **(Processing time):** Time taken to process a request ($T\_s \\ge T\_e$). The maximum processing time may vary depending on the specific device and request type. By default, it should not exceed **5 seconds**.  
* $T\_n$ **(Turnaround time):** Minimum delay between sending a response and receiving a new request. This depends on the communication interface implementation.

### **1.1 Interface: RS-232 / RS-485 / UART**

**Default Parameters:**

* Baud Rate: 9600  
* Data Bits: 8 (minimum)  
* Stop Bits: 1  
* Parity: None

**Timing:**

* $T\_s$**:** 4.5 character times  
* $T\_n$**:** 1.5 character times

### **1.2 Interface: TCP/IP**

**Default Parameters:**

* $T\_s$**:** 30 ms (usually configurable)  
* $T\_n$**:** None

## **2\. Transport Layer**

Data is transmitted in **Frames**. The protocol is addressable, supports broadcast requests, and validates request-response correspondence using IDs.

### **2.1 Frame Format**

* **Max Frame Size:** 255 bytes.  
* **Overhead:** 10 bytes (Technical fields).  
* **Max Payload:** 245 bytes.  
* **Byte Order:** Little Endian (LSB) for multi-byte fields unless specified otherwise.  
* **Floating Point:** IEEE.754 Single (FLOAT32) or Double (FLOAT64) precision.

| Field | Format | Size (Bytes) | Description |
| :---- | :---- | :---- | :---- |
| **ADDRESS** | BCD MSB | 4 | Device address. 0x00000000 is the Broadcast address (requests only). Responses to broadcast requests will contain the specific device address. |
| **FN** | UINT8 | 1 | Function Code. 0x00 is reserved for Error Responses (see Section 3.9). |
| **LEN** | UINT8 | 1 | Total frame length in bytes (including this LEN byte). Valid range: \[10...255\]. |
| **PAYLOAD** | BLOB | $\\le$ 245 | Data specific to the Function Code. |
| **ID** | UINT16 | 2 | Request Identifier. A pseudo-random number generated by the Master. The Device must respond with the same ID. |
| **CRC** | UINT16 | 2 | Cyclical Redundancy Check. Calculated over all data *excluding* the CRC field itself. |

### **2.2 CRC Parameters and Calculation**

**Characteristics:**

* **Standard:** CRC-16-IBM  
* **Polynomial:** 0xA001  
* **Initial Value:** 0xFFFF  
* **Start bit:** LSB  
* **Final XOR:** None

**C89 Implementation Example:**

\#include \<stddef.h\>  
\#include \<stdint.h\>

uint16\_t crc(void const \*data, size\_t size) {  
    uint8\_t i;  
    uint16\_t result \= 0xFFFF;  
    uint8\_t const \*buf \= (uint8\_t const \*)data;

    while (size--) {  
        result ^= \*buf++;  
        for (i \= 0; i \< 8; i++) {  
            result \= (result & 1\) ? (result \>\> 1\) ^ 0xA001 : result \>\> 1;  
        }  
    }  
    return result;  
}

**Validation Note:** When validating an incoming frame, calculate the CRC over **all bytes** (including the CRC field). If valid, the result will be 0x0000.

### **2.3 Frame Validation Algorithm (Device Side)**

1. **Length Check:** Is total bytes received $\\ge$ 10?  
2. **Address Check:** Is ADDRESS a valid BCD number?  
3. **Length Field Check:** Is received byte count $\\ge$ value in LEN field?  
4. **CRC Check:** Does calculated CRC match the received CRC field?  
5. **Target Check:** Does ADDRESS match the Device ID or is it Broadcast (0x00000000)?  
   * *If all pass:* Process Request.  
   * *If any fail:* Ignore Frame.

### **2.4 Frame Validation Algorithm (Master Side)**

1. **Length Check:** Is total bytes received $\\ge$ 10?  
2. **Address Check:** Does ADDRESS match the requested device (must not be Broadcast)?  
3. **Function Check:** Does FN match the request OR is it 0x00 (Error)?  
4. **Length Field Check:** Is received byte count $\\ge$ value in LEN field?  
5. **ID Check:** Does ID match the Request ID?  
6. **CRC Check:** Does calculated CRC match the received CRC field?  
   * *If all pass:* Process Response.

## **3\. Application Layer**

This section describes the payload formats for standard functions.

### **3.1 Structure: DATETIME**

Total Size: 6 bytes.

| Field | Format | Size | Description |
| :---- | :---- | :---- | :---- |
| **YEAR** | UINT8 | 1 | Years since 2000 (0-99). |
| **MONTH** | UINT8 | 1 | 1-12 |
| **DAY** | UINT8 | 1 | 1-31 |
| **HOUR** | UINT8 | 1 | 0-23 |
| **MINUTE** | UINT8 | 1 | 0-59 |
| **SECOND** | UINT8 | 1 | 0-59 |

*Note: If all bytes are 0xFF, date/time is considered "not set" or "missing".*

### **3.2 Structure: CHMASK**

Total Size: 4 bytes.

| Field | Format | Size | Description |
| :---- | :---- | :---- | :---- |
| **MASK** | UINT32 | 4 | Channel Bitmask. Bit 0 \= Channel 1, Bit 1 \= Channel 2, etc. |

### **3.3 Read Date/Time (FN: 0x04)**

* **Request:** Empty payload.  
* **Response:**  
  * DATETIME (6 bytes)

### **3.4 Write Date/Time (FN: 0x05)**

* **Request:**  
  * DATETIME (6 bytes)  
* **Response:**  
  * STATUS (UINT8): 0x00 \= Error, 0x01 \= Success.  
  * Z1 (UINT8): Pad (0x00).  
  * Z2 (UINT8): Pad (0x00).  
  * Z3 (UINT8): Pad (0x00).

### **3.5 Read Channels (FN: 0x01)**

* **Request:**  
  * MASK (CHMASK, 4 bytes): Mask of channels to read.  
* **Response:**  
  * CHANNEL1, CHANNEL2... CHANNELN (BLOB): Data for requested channels, sorted by channel index ascending.  
  * *Note: Size of data per channel is uniform. To find single channel size: (Payload Size / Num Channels).*

### **3.6 Write Channels (FN: 0x02)**

* **Request:**  
  * MASK (CHMASK, 4 bytes): Mask of channels to write.  
  * CHANNEL1... (BLOB): New values.  
* **Response:**  
  * MASK (CHMASK, 4 bytes): Mask of successfully written channels.

### **3.7 Read Archive (FN: 0x06)**

* **Request:**  
  * MASK (CHMASK, 4 bytes): **Must have only 1 bit set** (single channel per request).  
  * TYPE (UINT16, 2 bytes): Archive type.  
    * 0x0001: Hourly  
    * 0x0002: Daily  
    * 0x0003: Monthly  
    * 0x0004: Half-hourly (not supported by all devices)  
  * DATE\_START (DATETIME, 6 bytes).  
  * DATE\_END (DATETIME, 6 bytes).  
* **Response:**  
  * MASK (CHMASK, 4 bytes).  
  * DATE\_START (DATETIME, 6 bytes).  
  * VALUE1, VALUE2... (BLOB): Archive records.  
  * *Note: If a value has all bits set to 1, it indicates missing data.*

### **3.8 Read Parameter (FN: 0x0A)**

* **Request:**  
  * INDEX (UINT16, 2 bytes): Parameter Index.  
* **Response:**  
  * VALUE (BLOB, 8 bytes): Parameter value. Format depends on device map.

### **3.9 Write Parameter (FN: 0x0B)**

* **Request:**  
  * INDEX (UINT16, 2 bytes).  
  * VALUE (BLOB, 8 bytes). Unused bytes padded with 0x00.  
* **Response:**  
  * STATUS (UINT16, 2 bytes): Always 0x0000 (Success).

### **3.10 Error Response (FN: 0x00)**

* **Response:**  
  * CODE (UINT8, 1 byte): Error code.

**Standard Error Codes:**

* 0x01: Function code not supported.  
* 0x02: Invalid channel mask.  
* 0x03: Invalid length.  
* 0x04: Parameter missing.  
* 0x05: Write locked / Auth required.  
* 0x06: Value out of range.  
* 0x07: Archive type not supported.  
* 0x08: Max archive entries exceeded in single packet.

## **4\. Appendix**

### **4.1 Fixed (Reserved) Parameter Table**

| Parameter | Index | Access | Type | Format/Range |
| :---- | :---- | :---- | :---- | :---- |
| **Device ID** | 0x0000 | R | UINT16 |  |
| **Network Address** | 0x0001 | R/W | UINT32 | \[1...99999999\] |
| \*\*Password (Old | New)\*\* | 0xE000 | W | UINT64 |
| **FW Version Info** | 0x0002 | R | UINT64 |  |
| *\-- FW Number* | (Byte 0-1) |  | UINT16 | \[1...999\] |
| *\-- HW Version* | (Byte 2-3) |  | UINT16 | \[1...99\] |
| *\-- SW Version* | (Byte 4-5) |  | UINT16 | \[1...999\] |
| *\-- Revision* | (Byte 6\) |  | UINT8 | \[0...99\] |
| *\-- Modification* | (Byte 7\) |  | UINT8 | \[0...99\] |

### **4.2 Discovery Algorithm (Single Device, Unknown Address)**

1. Send **Read Parameter 0x0001** (Net Address) to Broadcast Address 0x00000000.  
2. Wait for Response.  
3. If response received: Extract Address from payload.  
4. Send **Read Parameter 0x0000** (Device ID) to the extracted address to confirm module type.

### **4.3 Discovery Algorithm (Multiple Devices)**

*Note: Not supported by all models.*

1. **Start:** Write to Parameter 0xE000.  
2. Wait 150ms.  
3. Check for response.  
4. If valid: Add to list (Address is in UINT32 LSB).  
5. **Next:** Write to Parameter 0xE001 to get next device.  
6. **Retry:** Write to Parameter 0xE002 if collision/error occurs.
